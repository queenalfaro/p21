
# ТЗ: Приложение для управления и координирования мероприятий

Мы создаем кроссплатформенное PWA-приложение для сопровождения офлайн и онлайн мероприятий.
**Главный UX-паттерн**: Приложение строится вокруг единой ленты (по аналогии с Telegram). И вообще весь UX/UI как аналогичные штуки в Telegram. Чат — это ядро. Все активности (опросы, оценки лекций, системные уведомления) отображаются не на отдельных страницах, а как специальные "кастомные сообщения" в общей ленте чата.

Целевые устройства: android.

> Всегда можно посмотреть результаты (различные метрики) комнаты - это должно быть целевой отличительной (от мессенджеров) фишкой приложения.

## Экраны

### Главный экран
- Кнопка "Профиль пользователя"
- Список доступных мероприятий пользователя
- Кнопка "Вступление в комнату"
- Кнопка "Создание комнаты"

### Профиль пользователя
- Кнопка "Переход на главный экран"
- Открытие по нажатию на кнопку "Профиль пользователя" на главном экране
- Поля для ввода данных и параметров пользователя

### Создание комнаты
- Кнопка "Переход на главный экран"
- Открытие по нажатию на кнопку "Создание комнаты" на главном экране
- Поля для ввода данных и параметров комнаты
- Кнопка "Переход в комнату"

### Экран комнаты
1. Header
- Кнопка "Переход на главный экран"
- Отображение основных данных комнаты (аватарка, название, дата проведения)
- При нажатии - переход на экран "Параметры комнаты"
2. Chat
- бесконечная лента сообщений в реальном времени
3. Footer
- Поле ввода текстового сообщения
- Раскрывающаяся кнопка-троеточие (список кнопок для отправки других типов сообщений)
- При вводе сообщения - появляение кнопки "Отправить"

### Экран профиля комнаты
1. Открывается при нажатии на Header на экране комнаты
2. Публичная зона (информация о комнате и настройки комнаты для пользователей)
- Вся информация о мероприятии (название, описание, статус, время и другие свойства, в будущем другие)
- Настройки пользователя (отключить уведомления и тп)
- Список участников
- Кнопка "Пригласить участника": открывает Share экран с кодом комнаты
3. Приватная зона (настройки комнаты для админов)
- Настройки для админов (редактирование данных, свойств и параметров комнаты)

### Share экран
- Template-экран, может открываться в любых местах где нужно поделиться чем-либо с другими людьми (как экран "поделиться профилем" в тг)
- QR код с данными
- данные в текстовом формате
- ссылка на данные
- кнопка поделиться

## Техническая реализация

PWA + SPA приложение

2. UI-компоненты не имеют права напрямую вызывать axios. Вся работа с сетью инкапсулирована в сервисах (папка src/services/). Компоненты вызывают методы сервисов (или actions из Pinia), а уже сервисы делают запросы. В будущем это позволит нам незаметно для UI переключаться между различными формами коммуникации с сетью (Firebase SDK/REST/WebSockets и др).
3. Мы не используем хардкод проверок вроде v-if="role === 'admin'". Бэкенд присылает массив разрешений (permissions). Используем хелпер: v-if="can('create_poll')".
4. Бизнес-логика не должна содержать вызовы аналитики. Если пользователь проголосовал, мы просто "кричим" об этом в глобальную шину: EventBus.emit('POLL_VOTED', pollId). Сейчас эти события уходят в пустоту, в будущем мы напишем сервис, который будет их слушать и собирать статистику.
